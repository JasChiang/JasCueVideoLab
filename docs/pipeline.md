# 完整流程參考

一支 60 秒的產品發表會影片，從 74 支毛片到成片，實際跑一次的樣子。
所有數字來自 2026-08-13 的 `artifacts/identity-full`：74 支素材、965 秒、
成片 49.5 秒 16 顆、總花費 $4.85。

---

## 一、誰回答什麼

| 問題 | 由誰答 | 用什麼看 |
| --- | --- | --- |
| 這支素材裡有什麼、可用區間在哪 | Gemini | proxy 640px 影片 |
| 這支素材裡有沒有那個產品 | Gemini | proxy 影片 **high 解析度** |
| 產品在第幾秒最清楚、框在哪 | Gemini | **母檔 1440px 靜態圖** |
| 這批素材該剪成什麼 | Gemini | 全部 proxy ＋ 音樂 ＋ Brief |
| 用哪幾顆、進點、運鏡 | Gemini | 可用的 proxy ＋ 定調 |
| 每顆多長、切在哪個拍點 | Gemini | 音樂 ＋ 鏡頭畫面 |
| 這一顆的畫格裡到底是不是它 | Gemini | **母檔 1440px 實際要用的那幾格** |
| 拍點落在第幾秒 | 本機 | onset 分析 |
| 攝影機有沒有在動、動多少 | 本機 | 母檔，192px @ 4fps |
| 哪幾秒對到焦 | 本機 | 母檔，640px @ 2fps |
| 主體逐格在哪 | 本機 | SAM 從 Gemini 給的框開始逐格追 |
| 裁切能移多遠、成本多少 | 本機 | 算術 |

原則：**語意問題給模型，量測留在本機。** 這不是信任問題 —— 是兩邊各自
只能回答一種問題，而失敗都來自問錯邊。

## 二、階段順序

```
proxy         每支壓一份 640px 給模型看（CRF 30，一支約 83 KB）
cards         逐支寫卡片：內容、可用區間、動作在第幾秒、聲音是不是內容
speech        Apple 辨識器給逐字時間，Gemini 改錯字並標出誰在講
─────────── 以下只有開 grounding 才跑 ───────────
identity screen      逐支問「這裡面有沒有鎖定的產品」
identity confirm     有的那些，逐支問「第幾秒最清楚、框在哪」
─────────────────────────────────────────────
direction     定調：長度、比例、節奏，以及每個鏡頭位的候選（primary + alternate）
commitments   本機把候選綁到不可變的段落，對不上就退回定調自己改（最多兩次）
selection     挑鏡頭：用哪幾顆、從第幾秒進、多長、什麼運鏡、框住誰
rhythm        每顆多長、切點怎麼對音樂
subject       SAM 逐格追出主體位置，算出裁切路徑
verify        逐顆對照它自己的宣告；沒做到的換替代品，重跑幾何
render        segments → concat → 配樂 → preview
review        （預設關閉）先逐顆對照計畫，再看整支
```

## 三、身分鎖的三層規則

Brief 若鎖定一個產品，規則有三層，缺一層就會出錯：

| 規則 | 實作 |
| --- | --- |
| 主體必須是那個產品 | 身分鎖 ＋ 逐顆驗證 |
| 環境鏡頭不需要產品入鏡 | 篩選判 absent 時**標記而非刪除**，`carries_identity=False` |
| 其他產品可入鏡但不能搶主體、不能被誤稱 | 環境素材宣稱有主角會被本機檢查擋下 |

沒有第二層時，會場、主視覺牆、展區人物會在規劃看到之前就被刪光 ——
一支體驗會影片裡不會有體驗會。

### 誰有權推翻誰

```
篩選（proxy 影片）      → 便宜的過濾器，沒有否決權
定調（同一批 proxy）    → 可以指名「這支有主角」，觸發升級
身分確認（母檔 1440）   → 升級後在這裡重新判
逐顆驗證（母檔 1440）   → 最終裁決
```

粗篩不得對更清楚的儀器有否決權。實測：同一支素材（C8379）在 low 解析度
下問四次，三次說沒有、一次說有 —— 兩顆相機圓環在 640px 上只有約 5 像素。
改成 high 之後判定翻正，而且本來就判對的否決沒有被放寬。

## 四、解析度是決策，不是檔案屬性

`video_resolution="low"` 的意思是**每格影片被壓成約 70 個 token**，
不管餵它 4K 還是 640px。所以：

- 把 proxy 做好一點，對篩選**零效果** —— 送進去就被打平了
- 要有差別只能提高 `video_resolution`
- `medium` 實測 token 數與 `low` **完全相同**，改了等於沒改

實測全量 74 支（965 秒）：

| 設定 | tokens | 費用 |
| --- | --- | --- |
| low | 755,783 | $1.28 |
| **high** | 937,290 | **$1.59**（實際 $1.44） |

靜態圖不受這個上限，所以「那台是哪一台」只能靠 1440 靜態圖回答。

## 五、快取：什麼會讓什麼失效

| 快取 | 金鑰 | 筆數 |
| --- | --- | --- |
| proxy | `content_hash(母檔)[:20]` | 90 |
| 素材卡片 | `content_hash(proxy)[:20]` | 80 |
| 攝影機運動 | `content_hash(母檔)[:20]` | 105 |
| 對焦 | `content_hash(母檔)[:20]` | 74 |
| 身分篩選 | `影片sha[:20]-lock[:16]-提示詞[:8]-解析度` | 456 |
| 身分證明 | `identity-影片sha[:20]-lock[:16]-提示詞[:8]` | （同上目錄） |
| 逐格判定 | `sha256(spec + target + 那幾格的 pts/sha)[:24]` | （同上目錄） |

**動 grounding spec 一個字，lock sha 就變，篩選＋身分證明＋逐格判定全部
作廢重付。** 這是最貴的錯誤：cue 要不要改必須在付錢前決定。

卡片與運動、對焦只綁素材本身，所以換 Brief、換 spec、重跑都免費。
提示詞與解析度進金鑰的理由相同：**它們是答案的輸入。**

## 六、修復迴圈：本機換，不重新規劃

逐顆驗證擋掉一顆之後：

1. 從定調階段就買好的 **alternate** 換上 —— 本機動作，不花錢
2. 沒有替代品的直接丟掉、片子縮短
3. 重跑幾何

實測第一次幾何之後的付費呼叫：

| 呼叫 | 次數 |
| --- | --- |
| `reference_exact_frame_bbox_batch` | 12（判定新換上那幾顆的畫格） |
| `rhythm` | 2（鏡頭換了，時間軸重排） |
| **`selection` / `direction`** | **0** |

三輪修復約佔總花費 19%，全部是「驗證從沒看過的畫面」。這正是
commitment-first planning 買到的東西：替代品一次買齊，換上去免費。

## 八、已知缺口

| 缺口 | 影響 |
| --- | --- |
| 沒有相鄰跳接偵測 | 同一個 set-up 的兩顆接在一起會讀成「突然推進」 |
| `plan_disagreements` 前端沒讀 | 有記錄，但軌道上標不出來 |
| 排序不讀測量值 | primary/alternate 只看文字理由，不看景別、構圖、運鏡空間、清晰度 |
| Brief 散文被當成字卡文案 | 解析器規則是「條列＝指示、散文＝文案」，整份用散文寫指示會誤判 |
| layout 備案沒人讀 | 「塞不下就用 40m」有抽出來，版面算不下時沒有程式碼去讀它 |
| 升級後未確認的素材仍是 carrier | 會浪費一輪修復才被逐顆驗證擋下 |
| 每輪修復重追所有鏡頭 | 花時間不花錢，但可以只重追換掉的 |
| 20 個常數單一樣本擬合 | 全部對著這一批素材調出來，沒在第二批素材上驗證過 |

## 九、看一次跑的結果

`report.json` 裡：定調、選片與每顆的理由、哪些切點落在音樂上、每個降級
處理與逼出它的量測值、逐顆是否做到宣告、花費分階段。

`work/` 裡：卡片、篩選結論、身分證明的畫格、選片、時間軸、裁切路徑，
每一個都是內容定址的中間產物 —— 這是重跑不重付的原因，也是出事時能
回頭看「它當時知道什麼」的原因。
